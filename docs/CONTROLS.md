# Player controls

How the real machine reads its controls, and how the core maps them onto the
Pocket. Behavioral reference: MAME `eprom.cpp` (Aaron Giles; see
`reference/NOTICE.md`) cross-checked against the SP-332 schematic — no code
copied, behavior reimplemented.

## The real hardware

Each player has a 2-axis **hall-effect joystick** — no switches, two analog
voltages. An **ADC0809** 8-channel ADC digitizes them; the 68k reads it at
0x260020-0x260027 (mirrored at +8), data in the low byte:

| Address  | Channel | Axis   |
|----------|---------|--------|
| 0x260020 | IN0     | P1 Y   |
| 0x260022 | IN1     | P1 X (reversed: 0x00 = full right) |
| 0x260024 | IN2     | P2 Y   |
| 0x260026 | IN3     | P2 X (reversed) |

A read returns the **last completed** conversion, and the same read strobe
latches the addressed channel and starts a new conversion (per MAME's
`adc_r`: `data_r()` + `address_offset_start_w(offset)`). The conversion takes
64 ADC clocks at 14.318 MHz/16 (~71.5 us = 512 core clocks); status bit
**ADEOC** (0x260010 D4, active high) is low while a conversion runs. The game
therefore reads a channel once to select it, polls ADEOC, then reads again
for the fresh value. Y axes read 0x00 = up; neutral is 0x80.

Buttons sit on the same input words, active low (schematic CD11..CD8):

| Bit | 0x260000 (P1) / 0x260010 (P2) | MAME     |
|-----|-------------------------------|----------|
| D8  | Jump                          | BUTTON2  |
| D9  | Fire                          | BUTTON1  |
| D10 | (unused)                      | —        |
| D11 | Duck                          | BUTTON3  |

## Emulation on the Pocket

`escape_core` carries a behavioral ADC0809 model (channel latch, 512-clock
conversion timer, ADEOC on 0x260010 D4) fed by four 8-bit axis ports.
`hall_stick` in `core_top` (`src/fpga/core/rtl/hall_stick.v`) produces those
axis values, one instance per player:

- **D-pad** presses are absolute deflections, like a hall stick held at the
  stop: released = 0x80, full press = 0x00/0xFF (X pre-reversed to match the
  harness). A subtle slew (~4.6 ms center-to-stop) mimics the physical stick's
  travel instead of teleporting the position between samples.
- **Analog stick** (dock / wired controller, `cont*_joy`): whenever it is
  deflected past a small deadzone it takes priority over the d-pad, so dock
  users get true analog control with no config option.

### Button map

Read off `core_top.v` `.p1_buttons` and cross-checked against `input.json`:

| Pocket        | Game            | `cont1_key` bit |
|---------------|-----------------|-----------------|
| Y             | Jump / Start    | 7               |
| B             | Fire            | 5               |
| A             | Duck            | 4               |
| X             | Bomb — asserts Jump+Fire+Duck together | 6 |
| Select        | Coin            | 14              |
| Start         | Self-test step / continue | 15    |

> **P2 bomb - FIXED in build 113.** `.p2_buttons` used to OR in
> `cont2_key[8]` (**L1**) where `.p1_buttons` uses `cont1_key[6]` (**X**),
> so X did nothing for P2 and L1 fired the bomb instead, contradicting
> `input.json`. P2 now reads bit 6, matching P1. This was the same
> bit-8-is-L1 confusion that produced the original P1 report.

### Debug controls

Not game controls — development tooling, and none of it is on by default.

> **These controls are OFF by default.** As of build 114 the whole
> diagnostic layer sits behind **Developer HUD** in the core's menu
> (`interact.json` id 38, default unchecked). With it unchecked, L1, R1,
> R and L2 do nothing and the overlay cannot appear -- a player never
> meets it. Tick it to get everything in this table back; no rebuild is
> needed, which is deliberate so that someone helping debug a report can
> turn it on without a toolchain. See docs/RELEASE_CHECKLIST.md section F.


| Pocket | Effect |
|---|---|
| **L1** | Show / hide the diagnostic HUD. **Starts hidden**, and does nothing at all unless **Developer HUD** is enabled in the core menu (see below). |
| **R1** | Cycle HUD page 0-6 (works with the HUD hidden; the page shows next time you press L1) |
| **L2** | Toggle the trace view |
| **R1 (hold)** | Hide motion objects |
| **L2 (hold)** | Hide the alpha layer |
| **R2 (hold)** | Video-fetch kill probe (screen garbles) |

The three hold-to-act probes are gated on the HUD being visible, so a player
cannot blank the sprites or the picture by accident. The cyan build number in
the bottom-right corner is drawn in both states and is not part of the HUD.

Per-page contents are in [`POCKET_TEST.md`](POCKET_TEST.md).

## Simulation

`./sim/run_tb.sh tb_escape_adc` proves the ADC path at the 68k-visible level
without any game ROM: a stub image (`sim/work/adc_words.hex`, hand-assembled
words only, regenerated by `run_tb.sh` via `sim/tools/make_adc_hex.py`) walks
all four channels the way the game does — select/start, poll ADEOC, read
back — and the tb checks the results landed in alpha RAM.
